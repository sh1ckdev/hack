# Соответствие обязательным функциям кейса МТС

Дата: 2026-11-21 · проект Relay Console · материалы: `data/`, `MTS-Codex-Guide.md`, презентация.

## Обязательные функции — где в продукте

| Требование | Реализация |
| --- | --- |
| **Четыре группы** | Сетка 2×2: критические, координаторам, высокий, исследование (`incidentGroups`, `index.tsx`). Пустые секции **всегда** на месте. |
| **Один INC в нескольких группах** | Одна карточка на секцию, общий `id`; `groups[]` на сервере; тесты `model.test.ts`. |
| **Автообновление из JSON** | Опрос файла ~1 с (`incident-store`), клиент `refetchInterval: 1000`. События: приоритет, срок, назначение, статус, удаление (`incidentChanges`). |
| **Продукт, время возникновения, исполнитель, статус, срок** | Карточка: продукт, `submitDate` (регистрация), статус, исполнитель/команда, `deadline`, таймер «осталось / просрочено». |
| **Клик → ITSM** | Ссылка на `INC` → `VITE_ITSM_INCIDENT_URL` или демо `/itsm-demo/:id` (`incident-destination.ts`). |
| **Критические выделены** | Колонка + рамка/бейдж P4, пульсация при появлении; снятие — `resolvedCritical` / уход из секции, зелёный статус на решённых. |
| **Оповещение: критический / координаторы** | Toasts + опционально звук/push (`shift-alerts`, `index.tsx` on fresh events). Способ настраивается в шапке. |
| **ИИ-анализ** | `POST /api/incidents/:id/analysis`, диалог «Сводка»; OpenRouter или `INCIDENT_AI_MODE=template`. |
| **Лёгкий UI** | Лента + 4 секции + компактная шапка; расширенные фильтры в выдвижной панели. |

В шапке: **`N в секциях · 44 в файле`** — сколько INC попало под правила четырёх очередей, не путать с полным JSON.
