# Контракт выгрузки инцидентов

Источники организаторов:

- `data/character_problems.json` — снимок (44 записи), рабочая копия для демо.
- `data/character_problems.source.json` — эталон для сброса (`pnpm demo:reset`).
- `data/incidents_attributes.json` — справочник полей и кодов.
- Презентация МТС «Инциденты в фокусе», `MTS-Codex-Guide.md`.

Корень выгрузки — массив объектов. Для демо считаем файл полным снимком. Исчезновение ID означает удаление из текущих очередей. Снимки сравниваются по ID; порядок строк и форматирование JSON несущественны.

## Приоритеты (`incidents_attributes.json`)

| `priorityId` | Подпись в справочнике | Группа дашборда |
| --- | --- | --- |
| 4 | Наивысший | «Критические» (только активные: `Assigned`, `WorkInProgress`) |
| 3 | Высокий | «Высокий приоритет» (активные) |
| 2 | Средний | — |
| 1 | Низкий | — |

В выгрузке на старте встречаются коды 1–3. Код 4 задаётся при демонстрации повышения приоритета (см. README, `INC000021938167`).

## Команда координаторов

Точное совпадение строки `assignedGroupName` с **«КЦ ИТ Координаторы Массовых Инцидентов»** (из кейса и выгрузки). Поиск по подстроке «координатор» не используется.

## Поля, используемые адаптером

| Поле исходного JSON | Правило и пример | Если отсутствует |
| --- | --- | --- |
| `id` | Непустая уникальная строка: `INC000021931151` | Снимок отклоняется, включая повторения ID |
| `sysId` | Строка: `179413934903718013`. Подстановка в ITSM | Ссылка с `{sysId}` недоступна |
| `productName`, `service`, `header` | Продукт, сервис, заголовок | Продукт — «не указан», остальное из заполненных полей |
| `description`, `shortDescription`, `solution` | Описание и текст решения. `solution` не определяет статус | Пустое описание допускается |
| `assignedEmployee`, `assignedGroupName` | Исполнитель и команда раздельно | «Не указан» / «Не указана» |
| `priorityId` | См. таблицу приоритетов | Нет групп по приоритету |
| `stateEnum`, `stateReason` | Логику задаёт `stateEnum` | Неизвестный статус показывается как есть, не считается активным или решённым |
| `submitDate`, `deadline`, `completionDate` | ISO 8601 с `Z` (UTC) | Нет таймера при пустом сроке |
| `productUrl` | В выгрузке пусто | Шаблон `VITE_ITSM_INCIDENT_URL` от организаторов |

Дополнительные поля справочника (`impactId`, `isMaster`, `scenarioName` и т.д.) сохраняются в JSON, но на группы и карточку не влияют, кроме участия в ИИ-сводке через описание.

## Статусы

Справочник перечисляет `stateId`: 0 — Назначен, 2 — Выполняется, 7 — Закрыт, 10 — Завершён. В выгрузке используется **`stateEnum`**; он может расходиться с подписями `stateId` в справочнике. При конфликте побеждает `stateEnum`.

| `stateEnum` | `stateId` в выгрузке | Пример | Правило |
| --- | --- | --- | --- |
| `Assigned` | 0 | `INC000021931151` | Активен |
| `WorkInProgress` | 2 | `INC000021930935` | Активен |
| `Resolved` | 7 | `INC000021929735` | Решён |
| `Closed` | 10 | `INC000021931571` | Закрыт |
| `Research` | 20 | `INC000021930418` | Сбой устранён, идёт исследование (кода 20 нет в справочнике — подтверждено выгрузкой) |

Очередь координаторов: активные записи и `Research`. Четыре условия групп вычисляются независимо (один ID в нескольких секциях).

## ITSM

`productUrl` — ссылка на продукт, не на карточку МИ. Переход в ITSM: `VITE_ITSM_INCIDENT_URL` с `{id}` или `{sysId}`. Без шаблона — локальная страница `/itsm-demo/:id`.

## API

- `GET /api/dashboard` — `runId`, `version`, `source`, `incidents` (с `groups`, `revision`), до 100 `events`. При ошибке чтения — `source.state: stale`. До первого успешного чтения — 503.

### События ленты (`events`)

Снимок сравнивается с предыдущим примерно раз в секунду. На каждую изменённую или удалённую запись формируется событие с полями `reasons` и при необходимости `detail` (человекочитаемый дифф).

| Причина | Когда срабатывает |
| --- | --- |
| `enteredCritical` / `newCritical` | Активный инцидент получил `priorityId: 4` |
| `leftCritical` | Снят активный критический приоритет (не через Research/Resolved) |
| `resolvedCritical` | Критический ушёл в `Research` / решён |
| `assignedToCoordinators` / `leftCoordinators` | Вход/выход из группы координаторов |
| `priorityChanged` | Смена `priorityId` без перехода в/из критических |
| `deadlineChanged` | Смена `deadline` |
| `assignmentChanged` | Смена `assignedGroupName` или `assignedEmployee` (не только координаторы) |
| `stateChanged` | Смена `stateEnum` |
| `removedFromExport` | ID исчез из JSON |

Порядок строк в файле и косметика JSON на события не влияют.
- `POST /api/incidents/:id/analysis` + заголовок `X-Relay-Request: summary` — сводка, `evidence`, `nextStep`, `revision`. Неизвестный ID — 404.
