# МТС Дежурка

Дашборд координатора массовых инцидентов для кейса МТС на Cyber Garden. Он читает JSON-выгрузку ITSM и показывает, какие заявки требуют внимания прямо сейчас.

На доске четыре очереди: критические, назначенные координаторам, высокого приоритета и на исследовании. Один INC может быть сразу в двух очередях. Например, критический инцидент после назначения координаторам остаётся в критических. Срок и статус на обеих карточках обновляются из одной записи.

Для общего экрана есть режим «Видеостена». На рабочем экране можно следить за заявкой, посмотреть историю передач и поставить общую отметку «Увидел» или «Беру в работу». Эти отметки видны на других экранах и хранятся отдельно от выгрузки ITSM.

## Запуск

Нужны Node.js 22.12+ и pnpm.

```sh
pnpm install --frozen-lockfile
npm run dev
```

Если pnpm остановит установку из-за скрипта сборки esbuild, разрешите сборку esbuild через `pnpm approve-builds` и повторите установку.

Откройте адрес, который выведет Vite. По умолчанию приложение читает `data/character_problems.json`. Файл уже в репозитории, ключи для запуска не нужны.

Чтобы читать другой снимок, укажите `INCIDENTS_FILE`. Переменная `VITE_ITSM_INCIDENT_URL` задаёт шаблон ссылки на заявку с `{id}` или `{sysId}`. Если оставить её пустой, номер INC открывает демо-страницу ITSM.

## Что показать

1. Откройте дашборд и найдите `INC000021938167` («Вечная зажигалка»).
2. Нажмите **Для демо → Сбросить и начать**. Затем применяйте шаги по одному.
3. Посмотрите, как заявка получает критический приоритет, появляется у координаторов и меняет срок сразу в двух секциях. После перевода на исследование она выходит из критической очереди.
4. Откройте **Сводка → Запросить сводку**, чтобы разобрать заявку. В **Смена началась** можно зафиксировать начало смены и позже скопировать бриф с изменениями.

Отдельные шаги можно запускать из терминала, пока дашборд открыт:

```sh
npm run demo:case -- --list
npm run demo:case -- critical-up
npm run demo:case -- coordinators
npm run demo:case -- deadline
```

Демо меняет JSON-файл. Для показа со своими данными укажите отдельную копию через `INCIDENTS_FILE`, а в CLI передайте тот же путь через `--file`. **Сбросить и начать** восстанавливает демо-данные на текущем сервере.

[Сценарий показа с командами](demo/README.md) и [шпаргалка для защиты](demo/MENTOR-GUIDE.md).

## Сводка и риск

Сводка строится по полям заявки. Чтобы подключить модель для формулировки сводки и оценки эскалации, возьмите настройки из [`.env.example`](.env.example) и сохраните их в `.env.local`. Для OpenRouter нужны `OPENROUTER_API_KEY` и доступный вашему аккаунту `INCIDENT_AI_MODEL`. Без модели доступна сводка по полям, а признаки риска и сроки считаются из выгрузки.

## Голосовой помощник

Whisper распознаёт речь локально. Кнопка «Голос» и сочетание `Alt+Shift+V` (на Mac `Option+Shift+V`) начинают запись, повторное нажатие её завершает. Попробуйте «Что мне сейчас взять в работу?», затем «Кто её ведёт?».

С локальным Qwen можно продолжить диалог в том же окне, исправить расшифровку и перейти к упомянутой заявке. Установка и запуск описаны в [VOICE.md](VOICE.md).

## Как устроено обновление

Сервер примерно раз в секунду читает и проверяет снимок JSON. Новую версию он сравнивает с предыдущей по ID и формирует события об изменениях приоритета, срока, назначения и статуса. Клиент запрашивает снимок примерно раз в секунду. Если чтение файла временно не удалось, остаётся последний корректный снимок.

Интерфейс написан на React и TypeScript. Локальные API и чтение JSON находятся в `server/`. Правила очередей и разбор полей описаны в [контракте выгрузки](docs/data-contract.md).

```sh
npm run build
```
