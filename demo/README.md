# Сценарий показа Relay Console

Для объяснения деталей менторам используйте [шпаргалку по требованиям кейса и устройству функций](MENTOR-GUIDE.md).

**Основной показ — 9–11 минут.** Ведём один инцидент `INC000021938167` («Вечная зажигалка») от высокого приоритета до передачи инженерам. Изменения вносит симулятор ITSM. Дашборд подхватывает снимки, выделяет события и помогает дежурному разобраться в очереди.

## Подготовка

В терминале из корня проекта создайте отдельную копию демо-выгрузки и запустите приложение:

```sh
DEMO_FILE="$(mktemp -d /tmp/relay-demo.XXXXXX)/character_problems.json"
cp data/character_problems.source.json "$DEMO_FILE"
printf '%s\n' "$DEMO_FILE"
INCIDENTS_FILE="$DEMO_FILE" npm run dev:voice
```

Откройте адрес из строки **Local** в выводе Vite в двух окнах. В одном включите «Видеостена», второе оставьте рабочим экраном. В рабочем окне снимите сохранённые фильтры, закройте старый личный фокус и проверьте доступ к микрофону. Если нужен чистый бриф с нуля, используйте отдельный профиль браузера. Проверка перед показом: произнесите «Что взять первым?», затем на тестовом инциденте проверьте «Запросить сводку» и «Оценить с ИИ», если доступна настроенная модель оценки риска.

Во втором терминале запустите помощник ведущего с путём, напечатанным первым терминалом:

```sh
npm run demo:show -- /tmp/relay-demo.XXXXXX/character_problems.json
```

**Enter** применяет один шаг, **q** завершает показ. После каждого шага дождитесь обновления дашборда и продолжайте с нужной реплики. Для показа без терминала используйте «Для демо» → «Сбросить и начать» → «Применить шаг» на экземпляре, запущенном с отдельной копией. Выберите один способ управления шагами.

## Что говорить и показывать

| Время | Действие на экране | Реплика и ожидаемый результат |
|---|---|---|
| 0:00–1:00 | Покажите видеостену и четыре очереди. Перейдите на рабочий экран и нажмите ненулевой показатель в «Риске смены». | «Команда видит одну оперативную картину. В верхней панели видно, где сроки уже прошли, что у координаторов и по каким продуктам открыто несколько заявок». Нажатие переводит внимание к соответствующей карточке. |
| 1:00–2:00 | Найдите `INC000021938167`. Откройте «Фильтры», включите критерий, покажите активную метку и сбросьте отбор. Нажмите «Следить» на карточке. | «На рабочем экране можно вытянуть нужную заявку из общей очереди и оставить её под наблюдением». Отбор и наблюдение действуют в браузере. |
| 2:00–3:00 | Откройте «Смена началась» и нажмите «Зафиксировать смену». Покажите «Могут стать критическими», откройте «Оценить с ИИ» до изменения приоритета, если модель доступна. | «Система показывает признаки возможной эскалации. Оценка раскрывает главный признак, объяснение и следующий шаг. Начало смены фиксирует точку отсчёта для передачи». |
| 3:00–4:15 | **Шаг 1.** Поднимите приоритет. Покажите сигнал, критическую колонку и обновление двух окон. Откройте «Сводка» → «Взять в личный фокус». | «Высокий инцидент стал критическим. Дашборд подхватил изменение. Для одного дежурного можно зафиксировать конкретный инцидент и затем увидеть, что изменилось за время работы». |
| 4:15–5:15 | **Шаг 2.** Назначьте координаторов. Покажите «История передач» и в сводке блок «Куда передать». Раскройте «Основания и примеры заявок», если появились варианты. | «Видна фактическая передача между командами. Подсказка опирается на другие заявки того же продукта и сервиса. Если сравнить не с чем, дашборд так и сообщает». |
| 5:15–6:15 | **Шаги 3 и 4.** Обновите срок, затем покажите две карточки. Нажмите «Связь». | «Это один INC в двух секциях. Срок обновился на обеих карточках. Связь помогает сразу понять, где ещё отображается заявка». Шаг 4 фиксирует состояние двух секций. Если оно уже наступило после назначения координаторам, отдельного нового события может не быть. |
| 6:15–7:45 | Нажмите **⌥⇧V**, спросите «Что взять первым и почему?» и снова нажмите **⌥⇧V**. Затем спросите «Кто её ведёт?» и «Что по ней менялось?». Нажмите «Открыть заявку». | «Помощник возвращает конкретную заявку, причину, срок и следующий шаг. В уточнениях он подставляет тот же номер и показывает реальные данные очереди». Если микрофон плохо слышит, покажите записанную репетицию или произнесите короткую фразу «Что взять первым?», а уточнения откройте кнопками на карточке ответа. |
| 7:45–8:45 | **Шаги 5 и 6.** Переведите заявку в исследование и верните инженерам. Покажите изменившиеся колонки, историю и результат личного фокуса. | «Заявка вышла из критических и перешла в исследование. После смены команды она ушла из очереди координаторов. Дежурный видит, что за это время поменялось». |
| 8:45–10:00 | В сводке заявки нажмите «Запросить сводку», покажите источник и «Протокол», затем откройте ссылку ITSM. Вернитесь и откройте «Смена началась» → «Копировать». | «В сводке есть то, что уже известно по заявке. Протокол переносит её контекст, а бриф смены собирает изменения после отметки старта. Следующий дежурный получает готовую точку входа». |

### Если есть ещё две минуты

- Откройте критическую заявку на рабочем ПК, введите имя смены и нажмите «Увидел», затем «Беру в работу». Покажите те же отметки на видеостене. Для демонстрации конфликта откройте второй профиль браузера с другим именем.
- В голосовом окне нажмите «Ввести текст» и спросите, кто исполнитель конкретного INC. Следом спросите «Какая команда ведёт её?». Покажите, что помощник сохранил контекст, а номер в ответе открывает заявку.

- Переключите тему, покажите настройки звука, push и «Фокус смены». Push зависит от разрешения браузера; проверьте его до выхода к жюри.
- Покажите голосовой отбор «Что у координаторов уже просрочено?» и «Сбрось фильтры». Если Qwen недоступен, простые команды по-прежнему работают.
- В панели фильтров покажите сортировку, отбор по команде, статусу и сроку, компактные карточки и скрытие пустых секций.
- Отдельно покажите смену исполнителя (`employee`), повторную передачу (`coordinator-roundtrip`), исследование у координаторов (`research-coordinators`) или исчезновение из выгрузки (`remove`). Эти шаги удобнее прогнать на новой копии.

```sh
npm run demo:case -- --list
npm run demo:case -- employee --file "$DEMO_FILE"
npm run demo:case -- coordinator-roundtrip --file "$DEMO_FILE" --wait 1500
```

**Финальная реплика:** «Мы только что прошли одну заявку целиком. На стене команда увидела изменение, координатор получил основания для передачи, а следующая смена получила историю и контекст».
